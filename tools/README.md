# Дымовой тест

Монтирует ВСЁ приложение в jsdom с реальным экспортом дневника и
щёлкает по всем вкладкам. Ловит то, что не ловит сборка: обращение
к переменной до её объявления, падение внутри рендера, ошибку в
одной вкладке при исправных остальных. Симптом таких ошибок —
пустой фон вместо приложения.

Появился после того, как обращение к `profile` из `useMemo`,
объявленного выше деструктуризации `const { profile } = state`,
уехало в прод: `vite build` прошёл без единого замечания.

    cd web
    npm i --no-save jsdom fake-indexeddb
    npx esbuild src/App.jsx --bundle --format=esm --outfile=appbuild.mjs \
      --define:import.meta.env='{"BASE_URL":"/monitor/"}' \
      --external:react --external:react-dom --external:react-dom/client \
      --external:react/jsx-runtime --jsx=automatic --loader:.css=empty
    node --experimental-default-type=module ../tools/smoke.mjs [путь-к-экспорту.json]

Код возврата 1, если в консоли были ошибки. «ПУСТО» в колонке
размера — вкладка не отрисовалась.

# Дымовой тест режима просмотра

Основной `smoke.mjs` монтирует приложение от лица родителя и до ветки
зрителя не доходит вовсе. Ошибиться там легко в обе стороны: спрятать
лишнее — зритель не увидит дневник; не спрятать нужное — кнопки на
месте, а нажатие молча ничего не делает, худший вариант из всех.

    cd web
    node --experimental-default-type=module ../tools/smoke-viewer.mjs путь-к-экспорту.json

Настоящий запрет всё равно на сервере: интерфейс проверяется на то,
что он не врёт, а не на то, что он защищает.

# Проверка модуля локальных уведомлений

    node --experimental-default-type=module ../tools/smoke-notify.mjs

Проверяет, что `notify-local.js` безвреден там, где плагина нет: в
вебе и в нативной сборке без установленного плагина. Именно этот тест
поймал, что возврат объекта плагина из async-функции роняет приложение
— рантайм принимает Proxy Capacitor за thenable и дёргает у него
`.then()`, а тот бросает исключение. Глазами такое не видно.

# Дымовой тест отзывчивости

    cp ../tools/smoke-perf.mjs ./_p.mjs
    node --experimental-default-type=module ./_p.mjs выгрузка.json

Проверяет не «работает ли», а «не подвисает ли» — то, что остальные
дымовые тесты пропускают полностью. Написан после того, как нажатие
«Заснул» блокировало поток на секунды: прогноз считался в теле рендера,
а кеши расчётов сбрасывались любой записью дневника, включая кормление.

Пороги с запасом: тест обязан ловить возврат СЕКУНДНЫХ задержек, а не
колебания в десяток миллисекунд от загрузки машины.

# Оценка алгоритма прогноза

    node --experimental-default-type=module ../tools/evaluate.mjs выгрузка.json

Walk-forward: для каждого дневного сна прогноз строится только по
данным строго до него. Считает попадания, медиану ошибки, сдвиг и —
главное — собственный разброс ребёнка, тот потолок, выше которого не
поднимется никакая модель.

`backtest.mjs` рядом умеет подменять константы (`loadModule({FIT_DAYS: 7})`),
чтобы мерить эффект правок алгоритма, а не спорить о них.

Запускать при каждом изменении алгоритма и просто по мере накопления
данных: верное на двух неделях может оказаться неверным на двух месяцах.

# Сравнение двух вариантов алгоритма

    node --experimental-default-type=module ../tools/ab-test.mjs выгрузка.json \
      'строка как есть в sleep.js' 'чем заменить'

Подменяет строку и прогоняет walk-forward оба варианта.

Смотреть надо на ПАРНУЮ разницу и z, а не на сводные проценты. На
60 наблюдениях разница медиан в 4 минуты уже возникала чисто от того,
куда попала середина распределения: сводные цифры показывали 20 против
16 мин, а парно — 0.2 мин и z = 0.89, то есть ничего. Пока z < 1.96,
изменение вносить не на чем.
